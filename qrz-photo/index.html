QRZ Setup Photo

During a POTA activation I send a photo of my setup from my iPhone, and it shows up on my QRZ page with a live ON AIR banner above it.

This page walks through how I built it, so someone comfortable with a Linux command line can follow along. It works for me, and I am still putting field time on it. I have trimmed the code to the parts that matter, so treat the snippets as the idea, not a drop-in copy of my files.

Just for fun. I built this because it was fun, and I post write-ups like this to give you ideas for your own projects. I can't help you build your own version or troubleshoot it, so please read this as inspiration, not a support page. Have fun with it, and 73!

The idea

I wanted the photo on my QRZ page to be the setup I am using right now, without logging in to QRZ from a picnic table. One tap in the share sheet should do it. The same photo upload also tells a small server to start watching for my spot, so the page can show whether I am on the air.

  1. iPhoneShare the photo to a Shortcut
  2. My serverSmall Python app saves it
  3. POTAServer checks spots every 5 minutes
  4. BannerFlickering ON AIR, or dim OFF AIR
  5. QRZBio embeds banner and photo

The rules I settled on for the banner:

  • Watching starts with a photo upload. No upload, no polling.
  • ON AIR while POTA has a spot for my callsign from the last 30 minutes.
  • OFF AIR after 30 minutes with no spot. If the newest spot's comment says QRT, I wait 10 more minutes for a newer spot, then go off.
  • Photo before the first spot: wait up to 30 minutes for a spot before giving up.
  • Off air keeps showing the last park, mode and frequency, so people know what the photo is.
Part 1

The server

You need a Linux machine that stays on. Mine is a small mini PC in the house. It needs Docker and a free Tailscale account. Nothing here needs a cloud server or a domain name.

The upload endpoint

The app is Flask with Pillow. The Shortcut posts the JPEG as the request body with a secret token in a header. The server checks the token, shrinks the image, and saves it. Saving a fresh JPEG with Pillow also throws away the EXIF data, so the GPS location that the phone camera recorded never reaches the public page.

import os, io, hmac
from flask import Flask, request, abort, send_file
from PIL import Image

TOKEN = os.environ["UPLOAD_TOKEN"]
app = Flask(__name__)

@app.post("/upload")
def upload():
    sent = request.headers.get("X-Token", "")
    if not hmac.compare_digest(sent, TOKEN):
        abort(401)
    img = Image.open(io.BytesIO(request.get_data())).convert("RGB")
    img.thumbnail((1600, 1600))          # keep it small
    img.save("/data/latest.jpg", "JPEG", quality=85)   # no EXIF written
    return "ok"

@app.get("/latest.jpg")
def latest():
    return send_file("/data/latest.jpg", mimetype="image/jpeg")

Run it in Docker

A tiny image is enough. I use gunicorn instead of Flask's built-in server, and I install a font package so Pillow can draw text for the banner later.

FROM python:3.12-slim
RUN apt-get update && apt-get install -y --no-install-recommends fonts-dejavu-core && rm -rf /var/lib/apt/lists/*
RUN pip install --no-cache-dir flask pillow gunicorn
WORKDIR /app
COPY app.py .
CMD ["gunicorn", "-b", "0.0.0.0:8090", "-w", "1", "--threads", "4", "app:app"]

Make a token, build the image, and start the container. The port is bound to 127.0.0.1 only, so nothing can reach the app except through Tailscale in the next step.

mkdir -p ~/qrz-photo/data && cd ~/qrz-photo
openssl rand -hex 24 > token.txt

docker build -t qrz-photo .
docker run -d --name qrz-photo --restart unless-stopped \
  -p 127.0.0.1:8090:8090 \
  -e UPLOAD_TOKEN="$(cat token.txt)" \
  -e WATCH_CALL="N9HO" \
  -v ~/qrz-photo/data:/data qrz-photo

Keep the token private. It is the only thing that stops a stranger from replacing your photo.

Put it on the internet with Tailscale Funnel

Funnel gives a local port a public HTTPS address with a real certificate, with no router changes and no port forwarding. The first time, you may need to turn Funnel on for your tailnet in the Tailscale admin console.

sudo tailscale funnel --bg 8090
tailscale funnel status

The status command prints your public address, which looks like https://your-box.your-tailnet.ts.net. Test it from outside your house with a phone on cellular. A request without the token should come back 401.

Testing tip. Tailscale routes your own devices straight to the box over the tailnet, so a test from a phone with Tailscale turned on does not prove the public path works. Turn Tailscale off on the phone when you check.
Part 2

The iPhone Shortcut

The Shortcut shows up in the share sheet for photos. Build it in the Shortcuts app:

  1. Create a new Shortcut and turn on Show in Share Sheet, accepting Images.
  2. Add Convert Image and set it to JPEG. iPhones save HEIC by default, and Pillow does not read it out of the box.
  3. Add Get Contents of URL. Set the URL to your Funnel address followed by /upload. Set the method to POST.
  4. Under Headers, add a key named X-Token with your token as the value.
  5. Set Request Body to File and choose the converted image.
  6. Add Show Notification so you see "ok" when it lands.
Two things that tripped me up. The Method, Headers and Request Body rows did not appear until I left the Shortcut editor and reopened it. And I first typed the token into the value field without a key name, so the header never got sent. The key has to read X-Token.
Part 3

Watching POTA for my spot

POTA publishes current activator spots as plain JSON, with no login. Spots from the Reverse Beacon Network show up there too, so a CW activation gets picked up even if nobody spots me by hand. One call returns everything:

https://api.pota.app/spot/activator

Each spot has the fields I need: activator, reference, name (the park name), frequency in kHz as a string, mode, spotTime in UTC, comments, and source. The app picks out my callsign, including portable forms like N9HO/P, and takes the newest spot:

import json, re, urllib.request

CALL = "N9HO"
URL = "https://api.pota.app/spot/activator"

def latest_spot():
    with urllib.request.urlopen(URL, timeout=15) as r:
        spots = json.load(r)
    mine = [s for s in spots
            if CALL in str(s.get("activator", "")).upper().split("/")]
    return max(mine, key=lambda s: s["spotTime"], default=None)

def says_qrt(spot):
    return bool(re.search(r"\bQRT\b", spot.get("comments") or "", re.I))

A background thread runs this every 300 seconds after an upload and keeps a small state record (status, last spot time, QRT time, and the park info) in a JSON file in the data folder, so a restart does not lose it. The state moves between three values: off, watching (photo received, no spot yet), and on. The rules from the top of this page are the only logic.

Testing tip. Test with a callsign that is on the air right now. I first tested with a callsign that only showed up as a spotter, and it correctly stayed on "watching" forever. Set WATCH_CALL to an active activator, confirm the banner flips, then set it back to yours.
Part 4

The banner

The banner is a 600 by 130 pixel GIF that Pillow draws on request. On air, it has a red light, "ON AIR", my callsign, the park reference and name, and a line with mode, frequency and band. The flicker is a handful of frames with different glow strength, saved as a looping animated GIF. Off air, it is one dim frame with "OFF AIR" and a "Last:" line for the most recent park.

frames = [draw_frame(True, glow, info) for glow in GLOW]
frames[0].save(buf, "GIF", save_all=True,
               append_images=frames[1:], duration=120, loop=0)

The server exposes the banner at /status.gif and the raw state at /status.json, which is handy for debugging. A GIF works well here because it needs no JavaScript, and QRZ will not run any.

Then one more route ties it together: a small HTML page that shows the banner above the photo, and reloads itself every five minutes.

<!doctype html>
<html><head><meta charset="utf-8">
<meta http-equiv="refresh" content="300">
<style>
html,body{margin:0;background:#111114;}
.wrap{width:600px;margin:0 auto;}
img{display:block;width:600px;}
.photo{margin-top:8px;height:450px;display:flex;align-items:center;justify-content:center;background:#0b0b0d;}
.photo img{max-width:600px;max-height:450px;width:auto;height:auto;}
</style></head><body><div class="wrap">
<img src="/status.gif" alt="Station status" width="600" height="130">
<div class="photo"><img src="/latest.jpg" alt="POTA setup"></div>
</div></body></html>

Serve that at /card with a Cache-Control: no-cache header so visitors always get the current photo.

Part 5

Getting it onto QRZ

This is the part with a catch. QRZ's bio editor wants images hosted on QRZ, and it strips ordinary <img> tags that point at other sites. A live banner cannot be a QRZ-hosted image, because it has to change.

What does survive is an iframe. QRZ renders your bio inside a sandboxed frame, and it keeps an iframe that points at another page. Other hams use the same trick for Club Log and HRDLog widgets. In the bio editor, click Source and paste this at the top, using your own Funnel address:

<p style="text-align:center"><iframe src="https://your-box.your-tailnet.ts.net/card" width="620" height="600" frameborder="0" scrolling="no"></iframe></p>

Save, then view your public page. The card sits above the rest of your bio, and the banner and photo update on their own.

Be honest about the risk. This leans on how QRZ renders bios today, and it is outside what their editor rules describe. QRZ could change it. If they block the frame, nothing breaks on your server. The card still works at its own address, and you can link to it from your bio instead.

Things I would tell you before you start

  • The photo upload is the trigger. If you are on the air and nothing shows, send a photo and give it up to five minutes.
  • CW and digital activations get spotted automatically once you declare them on pota.app. For SSB you need to self-spot.
  • The token is the only lock. Use a long random one, and do not paste it anywhere public.
  • Strip location data from photos you publish. Re-saving through Pillow does it for you here.
  • Keep the container bound to localhost and publish it only through Funnel, so there is one door in.
